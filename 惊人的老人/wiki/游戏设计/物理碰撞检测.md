# 物理碰撞检测

物理引擎负责让物体「表现得像真的」：受重力下落、碰撞反弹、摩擦减速。以 Unity 底层的 PhysX 为例，它**不是逐帧连续检测**，而是每隔固定时间（默认 0.02 秒）做一次「快照式」的离散碰撞检测。

> 三份百科词条（11-07 的碰撞检测、11-12 与 11-14 的补充），`confidence: low`。参数与 API 名称未回查官方文档。

## 为什么值得知道

**离散检测的代价是「两帧之间可能跨过障碍」。** 物体够快、墙够薄，上一帧还在墙前、下一帧已在墙后，中间那片空间从没被采样过——这就是穿墙。

引擎给的兜底是**连续碰撞检测（CCD）**：把这一帧的运动轨迹当成一条线段去求交，代价是更耗性能。所以实践中的形态是「绝大多数物体用离散，少数高速物体开 CCD」。

理解这套机制的价值不在实现，而在**定位**：

- 子弹穿人、角色掉出地图、掉落物穿过地板——这些经典 bug 的第一嫌疑人是检测模式
- 但不是所有都是。判定盒（hitbox）与射线检测属于另一套系统，混着查会跑偏

## 示例

- **Unity（2005 至今）**：把 Rigidbody 的 Collision Detection 由 Discrete 改为 Continuous Dynamic，可防止高速物体穿透
- **《任天堂明星大乱斗》**：靠帧间插值与判定盒设计规避这类问题

## 步长：碰撞检测的上游变量

「默认 0.02 秒一次快照」不是引擎的偏好，而是**固定时间步长（fixed timestep）**的产物：每帧只推进固定的 1/60 秒，用累加器把真实流逝的时间攒够一份再模拟。Unity 的 `FixedUpdate` 就是这条路径，`Update` 才是可变步长。

为什么必须固定：**物理结果依赖步长。** 同一个跳跃，30 帧和 144 帧下落地位置不一样；步长太长，快速移动的物体直接穿过墙——这就是上文的穿墙根源。固定步长让结果与帧率脱钩，可复现、可回放、可联网同步；代价是要做渲染插值，否则画面看着一顿一顿。

所以「穿墙」有两个独立病因：**单帧位移超过碰撞体厚度**（设计侧：加速度、碰撞体尺寸），和**步长与渲染帧率不匹配**（工程侧）。调前者不解决后者。

## 粗筛：先分区，再精算

上面两步（步长、CCD）解决的是「一次判定准不准」，还有一层是「要判多少次」。不去分区，N 个物体两两检测就是 N×(N-1)/2 次：200 个物体在无序口径下约 1.99 万次，500 个约 12.5 万次——低端机上光这一项就能吃掉一帧。

**空间分区（四叉树是最常见的一种）**的做法：把地图看成一个矩形，某块区域里的物体数超过阈值（通常 4~8 个）就把这块切成四份、递归切下去，形成一棵每个节点四个孩子的树。每个物体只归到自己所在那格，查「谁可能撞到我」时只看本格与邻格。复杂度从 O(n²) 压到接近 O(n log n)。

三条使用上的注意，词条都点到了：

1. **它只是粗筛。** 筛出候选对之后还要做精确判定（圆形距离、多边形相交），否则四叉树会给出「可能撞」而不是「撞了」
2. **物体频繁移动时，每帧清空重建通常比逐个更新更省心**——增量更新一棵动态树的分支代价，往往高于重建
3. **阈值（4~8）决定树的形状**，不是常数；区域内物体密度不均时，树会退化成链表

> 词条给的案例是腾讯光子《最强魔斗士》（2020）用四叉树给子弹做空间规划，每颗子弹每次只与 0~2 个障碍物算碰撞。这是生成方说法，`confidence: low`。

## 反论与缺口

- **0.02 秒是默认值，不是常数。** 它是固定时间步长（fixed timestep），可以调；调小更精确但更贵。词条把默认值写成了机制本身。
- **「子弹穿人」多数不是 CCD 问题。** 射击游戏普遍用射线检测（hitscan）或独立判定盒，根本不过物理引擎。把这个 bug 归到离散碰撞上，是归因错位。
- **大乱斗的例子与 PhysX 不是同一类问题。** 格斗游戏普遍自研帧同步判定，谈「插值规避穿透」和物理引擎的 CCD 是两套语境，并排放会误导读者以为可以照搬。
- **CCD 的开销量级没给。** 「更耗性能」是定性说法，缺具体量级，无法用来做预算决策。
- **「200 个物体近 4 万次」用的是有序对口径**（200 × 199 ≈ 3.98 万）。按无序对（A 与 B 只算一次）只有 19900 次。词条用有序口径讲复杂度没有错，但拿它当「一帧实际要算多少次」会高估一倍。
- **「接近 O(n log n)」忽略了树的维护成本。** 插入/删除、每帧重建的分配开销（在带 GC 的引擎里尤其明显）、节点遍历的常数，都可能吃掉理论收益；物体越动态，实际收益越小。词条把它写成了纯收益。
- **「每颗子弹只与 0~2 个障碍物算」是最好情况。** 障碍物密集的走廊里候选数会翻几倍；这个数字更像宣传点，不是上界。
- **未验证**：新版 PhysX 与 Unity 物理后端在该参数上的默认值是否仍为 0.02 秒。
