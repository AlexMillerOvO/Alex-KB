# AI 写任务线与世界设定

用 AI 生成叙事内容时，真正的难点不是「能不能写出来」，而是**写长了会不会自相矛盾**。本篇记录两种已验证的做法：把生成拆成互相依赖的多个阶段、以及让独立的审查 agent 卡住质量。

> 两篇 arXiv 预印本，均未同行评审，`confidence: low`。量化结果均为作者自报，未独立复现。

## 问题

RPG 的任务线和世界设定有一个共同特征：**后面的内容依赖前面的内容**。任务 B 的前提是任务 A 发生过的某件事；某个 NPC 的动机要和他所在地区的设定一致。

直接用大模型一次性生成，会遇到三类失效：

1. **叙事漂移**：生成到第 N 个任务时，已经忘了第 1 个任务里定下的事实
2. **幻觉**：凭空出现前面没提过、后面也不再出现的地点或人物
3. **上下文爆炸**：世界设定越写越长，很快就超出模型的上下文窗口

第三点尤其致命——它意味着「多写几轮让内容更丰富」这条直觉路径走不通。

## 方案

两种做法，针对上面不同的失效模式。

### 做法一：依赖驱动的阶段化流水线（任务线）

把生成拆成固定顺序的几个阶段，前一阶段输出**结构化 JSON**，后一阶段以它为条件：

```
世界构建 → NPC 创建 → 玩家角色创建 → 战役级任务规划 → 任务展开
```

关键在于每一步的输出都是受 schema 约束的 JSON，而不是自由文本。这样「上一阶段定下的事实」变成了机器可校验的数据结构，而不是需要模型自己记住的散文。

来源：[[raw/2026-11-03_arxiv_2604.25482_from-world-gen-to-quest-line-a-dependency-driven-prompt-pipe.md]]

### 做法二：生成与审查分离 + 上下文压缩（世界设定）

AutoWorldBuilder 系统用五个组件解决世界构建：

| 组件 | 解决什么 |
|---|---|
| 结构化概念网络（带冲突检测） | 内容自相矛盾 |
| 基于 DAG 的混合批调度（按语义局部性分组） | 生成顺序 |
| 四层上下文压缩（约 90% token 削减） | 上下文爆炸 |
| 迭代审查 + 8 个专门 Auditor | 质量没有把关 |
| 技能驱动的 agent 架构（零代码扩展） | 扩展成本 |

审查 agent 与生成 agent **架构上相互独立**，用来规避「自己生成自己批准」的偏差。

来源：[[raw/2026-11-03_arxiv_2607.09403_fictional-worldbuilding-multi-agent-llm-collaboration-with-h.md]]

## 可行性卡

| 落地形态 | 依赖 | 成本量级 | 已验证范围 | 等级 |
|---|---|---|---|---|
| 阶段化 prompt 流水线（你自己搭） | 通用大模型 API + JSON schema 校验 | 低（无需训练，纯工程） | 多轮独立运行的定性人工评估 | **A** |
| AutoWorldBuilder 式多智能体系统 | GPT-OSS 120B / DeepSeek v3.2 级模型 + 多 agent 编排 | 中高（需 120B 级模型，本地部署或大额度 API） | 20 个多样化世界构建任务 | **B** |

**关键量化结果**（均来自摘要，作者自报）：

- 任务线流水线：随复杂度上升**未出现质量退化**；把「战役级规划」与「任务展开」分开后，全局结构和局部叙事都更好
- AutoWorldBuilder：提案通过率从首轮 **42%** 提升到 **85.5%**；每个世界生成 **56–103 个自洽概念**，耗时 **18–31 分钟**；最终输出中审查系统未检出冲突；两个实验共 20 个任务，**成功率 95.0%**

## 权衡

| 做法 | 优势 | 代价 |
|---|---|---|
| 阶段化 + JSON schema | 不需要训练模型，纯工程改造；通用大模型即可 | 每个阶段都要设计 schema，前期设计工作量大 |
| 生成/审查分离 | 通过率可从 42% 提到 85%+，且能规避自批准偏差 | 需要额外一轮模型调用，成本与延迟翻倍 |
| 上下文压缩（90% token） | 世界设定可以持续写下去而不炸上下文 | 压缩本身可能丢细节；四层压缩机制实现复杂 |

**这两份资料都没有给出的**：真实项目里的返工率是多少、生成的任务线玩家实际玩起来体验如何、以及中文语境下的效果。

## 示例

**任务线**（依赖驱动流水线）：五阶段依次生成，每阶段输出受 schema 约束的 JSON。作者用「多个独立运行」做以人为中心的定性评估，评估维度包括结构完整性、内部一致性、叙事连贯性、多样性、可执行性。

**世界设定**（AutoWorldBuilder）：以 GPT-OSS 120B 和 DeepSeek v3.2 为后端，20 个任务上 95.0% 成功率；单世界产出 56–103 个概念、18–31 分钟、零冲突交付。8 个专门 Auditor 并行评分（一致性权重最高，1.5），未通过者进入「修订—重评」迭代，最终按 Top-K（默认前 70%）筛选。

## 变体与待验证

- **审查 agent 的独立性**：本文引用的两篇都强调「生成与审查分离」。但这个设计只在 AutoWorldBuilder 一篇里有量化支持
- **上下文压缩的迁移性**：90% token 削减是在「世界构建」这个特定任务上测的，任务线或关卡生成是否同样有效未知
- **中文模型上的表现**：两篇均只用英文/开源模型验证，中文叙事生成未见数据

## 反论与数据缺口

- **任务线那篇只有定性评估**，没有量化指标：摘要明确说「evaluated qualitatively through human-centered analysis」。42%→85.5%、95.0% 这些数字全部来自 AutoWorldBuilder 一篇，**不能代换到任务线流水线上**
- **AutoWorldBuilder 的 95% 成功率是「任务成功率」**，不是「内容质量分」。它衡量的是系统跑完没跑完，不等于产出的世界观好不好
- **两篇都未做玩家侧验证**：生成出来的内容有没有人真的玩过、体验如何，两份资料都没回答
- **模型依赖是硬门槛**：AutoWorldBuilder 用 120B 级模型。用小模型（如 7B）能否达到同样效果，文中未提及
- **「零冲突」是审查系统自己判的**：如果 Auditor 本身有盲区，那么「zero-conflict delivery」这个结论的强度要打折
