# 玩家需求八分类

把「玩家为什么还想继续玩」拆成 8 类可判定的需求：A 完成感 / B 成长感 / C 收集感 / D 效率感 / E 稀缺感 / F 惊喜感 / G 证明感 / H 归属与习惯。

这套分法不给每类写定义段，而是给**一句判定标准 + 一条反例**。原因很实际：分类真正的作用不是命名，是防止把同一个系统放错抽屉——放错了，后面挂上去的方法就全错了。

> 单一来源：某塔防改版项目的内部设计文档（`raw/2026-11-11_小目标设计方法库.md`），未公开发布、无第三方验证、无效果数据。`confidence: medium`。**这是单一项目的内部设计口径，不是行业调研结论**，不能读成「某公司验证过的分类」。

## 判定标准与反例

| 类 | 名称 | 判定标准（玩家的满足来自哪句话） | 反例 |
|---|---|---|---|
| A | 完成感 | 「这件事结束了」 | 「我把所有部位集齐了」属于 C，不是 A |
| B | 成长感 | 「同一件东西变强了」 | 「我多了一个槽位可以镶」属于 C（容器变多），不是 B |
| C | 收集感 | 「凑满了 / 凑齐了」 | 「我洗出了想要的词条」属于 B（变强），不是 C |
| D | 效率感 | 「少花时间 / 少点几下」 | 一次批量合成了三个，但仍是一个个滚出来的，属于 B 的连续结果，不是 D |
| E | 稀缺感 | 「在有限资源下做了正确取舍」 | 「我攒够了所以能升」属于 B，不是 E |
| F | 惊喜感 | 「没想到，但挺好」 | 保底出货是确定性的兑现，保底本身归 B / D |
| G | 证明感 | 「我证明了自己 / 我和别人不一样」 | 一旦挂上排行榜就变成攀比；没有榜单时只能自比 |
| H | 归属与习惯 | 「这是我的故事」或「不来会亏」 | 因为体力自然恢复而每天上线，属于 E，不是 H |

两对最容易糊的分界：

- **B 与 C**：B 是「同一件东西变强」，C 是「不同的东西凑多」。把槽位镶满是 C；把已镶的部件从碎片升到完整是 B。
- **E 与 F**：E 是玩家主动算，F 是系统给意外。递增消耗逼玩家算「这一局该召唤还是该强化」是 E；按权重随机出一条词条是 F。

## 为什么值得知道

**一、分类的单位是「玩家心里那句话」，不是系统名。** 所以「这个系统属于哪一类」是个提错的问题。同一套精炼系统可以同时挂三类：给成长（品质区间往上走）、给惊喜（词条随机）、给稀缺（锁定想保留的词条要加价）。该问的是：我要玩家在这一屏说哪句话。

**二、反例比定义有用。** 同一件事换个说法就换类，说明判据是**满足来源**，不是功能形状。这也是审查工具：一个系统如果挂不上任何一类，它大概只是「加了一个功能」。

**三、它把「变化」和「凑数」拆开了。** 这是实际设计里最容易糊的一处：加一个槽位（C）和让已有东西变强（B），在 UI 上都是「我变强了」，但玩家重复做这两件事的疲劳曲线不一样。混在一起谈，就会做出「槽位越加越多、单件东西永不变强」的系统。

## 与既有体验分层的映射

来源文档把八类对齐到同一项目的另一套五层体验口径（操作 / 成长 / 判断 / 习惯 / 追回）。按本文的读法，两者是两种维度，不是替代关系：

- 五层按**玩家在什么尺度上做决定**分层：这一局内 / 长线养成 / 一次消费决策 / 日循环 / 流失挽回。
- 八类按**满足来源**分层，是每条设计方法的挂载点。

拿五层当分类会得到太粗的桶（成长层把 B 和 C 合并了，而这两类的设计后果完全不同）；拿八类当节奏表会得到一堆没有顺序的点（65 条方法之间没有先后）。**讲体验节奏用五层，挂具体方法用八类。**

## 反论与缺口

- **没有效果证据。** 来源文档的自我审查只查三件事：载体可查、不编数值、不越红线。**没有一条查「玩家是否因此留下」**。八类是一个组织信息的框架，不是被验证过的动机模型。
- **分类不正交，原文自己承认。** 风险列标出至少四组「同一机制、两个用途」：领主养成总和既算复利链条（B）又算刻度自证（G）；战斗数据面板既是省事查数（D）又是自证强（G）；章节进度既是完成（A）又是全清（G）；随机槽位既是成长路径（B）又是随机惊喜（F）。四组同源说明八类更像标签集合，不是互斥维度——把它当正交分类去做覆盖率统计会得出假结论。
- **G 类分类成立、载体缺失。** 砍掉排行榜后 G 类只剩自比，而同一份文档的缺口清单承认「没有历史最佳记录」。这说明分类的完整性不等于方法的完整性。
- **反例是作者判断。** 「洗出想要的词条属于 B 不属于 C」这类划线没有玩家测试支撑，属于设计者视角的分类约定。
- **未验证**：八类之间是否存在权重差（哪一类对留存贡献更大）；跨品类（买断制、休闲、竞技）是否同样成立。
- **口径必须带定语。** 这套分类出自一个具体项目的内部文档，作者是该项目策划。引用时要说「某项目把玩家需求分成八类」，不能说「行业把玩家需求分成八类」。

## 与其他知识的关联

- [[小目标拆解]] — 这份分类的下游：八类回答「要什么」，那篇回答「怎么给」，两页共用同一份来源
- [[再来一回合]] — 「马上就能做完的小目标」正落在 A 与 B 之间；那篇留着的开放问题（小目标提示给几个）在这套分类里同样没有答案
- [[抽卡保底机制]] — 保底被归入确定性（B / D）而不是惊喜（F），这是全表最反直觉、也最有用的一条划线
- [[装备词条池]] — 词条池同时踩 F（随机）与 B（变强），是「一个系统挂多类」的典型样本
- [[肉鸽三选一]] — 三选一是 E（有限资源下取舍）与 F（选项随机）的混合，不是单纯的「给选择」
- [[时间与体力的双预算]] — 双预算把 E 类从「资源不够」变成「要规划」，与这里把稀缺感定义成「做了正确取舍」是同一件事
- [[降低回归成本]] — H 类的反面对照：玩家断档之后，八类里没有一类负责「把他拉回来」

## 开放问题

- 八类里哪一类最容易被拿来当「再加一个系统」的借口？
- 一款产品如果只做三类，选哪三类最稳？
- 分类能不能反过来当砍需求的审查表：挂不上的系统，是不是就该砍？
