# 贴图图集（Texture Atlas）

把几十上百张小图拼进一张大图，每张小图记住自己在图集里的像素矩形；渲染时不用换贴图，只把 UV 指到对应那一格。

> 单一二手来源（百科词条），`confidence: low`。引擎细节以 Unity 手册为准，未逐条回查。

## 本质是一道装箱题

把矩形塞进固定面积里，尽量少浪费。所以它有两个天然约束：**总面积有上限**（设备纹理上限），**排布有碎片**（不同尺寸的图混装会留下空洞）。

## 为什么值得知道

一次 draw call 的前提是同一张贴图、同一个 shader、同一种混合模式，换任何一样就要断批。所以 UI 图标、特效序列帧、地块这些东西必须进图集——Unity 文档写明，同一个 Sprite Atlas 里的精灵只需一次 draw call。

三个实在的坑：

| 坑 | 后果 |
|---|---|
| 格子间不留 padding（常见 1~2 px）与边缘扩边 | 双线性过滤会采样到隔壁格子的颜色，出黑边或彩边 |
| 尺寸超设备上限（常见 4096 / 8192） | 上传静默失败，整张图变白，且不一定报错 |
| 图集切得太碎或太大 | 切换图集本身就要断批；大图集改一个图标要重传整张，加载粒度变粗 |

## 例子

《星露谷物语》（2016）把所有道具图标放在同一张 16×16 一格的图集里，mod 作者换一张 PNG 就能替换全部图标——图集顺带成了 mod 接口。

## 上游：纹理压缩决定图集能有多大

图集能拼多大，受限于显存与带宽，而这两者由压缩格式决定。

贴图默认是「每像素 4 字节」，一张 4K RGBA 图就要 64MB。GPU 块压缩把它切成 4×4 或更大的块，每块只存几个代表色加索引表，压到 1/4 甚至 1/8；**关键是显卡能直接在上面采样，不用先解压**。

| 平台 | 格式 | 要点 |
|---|---|---|
| PC | BC 家族 | BC7 画质最好；BC5 专门留给法线贴图 |
| 移动 | ASTC | 块大小 4×4 ~ 12×12 可选；原神移动端基本只打包 ASTC |

两个工程结论：

1. **省显存是次要收益，真正卡移动端的是带宽与功耗**——从 8bpp 降到 3.56bpp 等于少读一半以上数据，直接换成帧率与续航。《王者荣耀》用 ASTC 时显存约 400MB，不压缩会涨到 1.4GB。
2. **法线贴图不能当普通颜色图压**，否则光照出现棱状断层——这是图集分组时最容易踩的坑：法线、遮罩、颜色三类要分开打包。

顺带一条成本：跨平台要转码。原神云游戏服务器要把 ASTC 转成 PC 的 DXT，每个实例光转码就多花 20 秒以上。

## 反论与缺口

- **图集不是无成本的。** 运行时切换图集同样断批，多图集方案要按「同屏出现频率」分组，而不是按美术分类分组。
- **大图集与加载粒度是一对矛盾。** 移动端尤其明显：图集越大，首包与增量更新越难做，热更时改一个图标可能推整张图。
- **压缩格式的块对齐会吃掉 padding 的作用。** ASTC / ETC2 按 4×4 或 6×6 块压缩，padding 不足时扩边也救不回来，这条词条没提。
- **未验证**：Unity Sprite Atlas「一次 draw call」的成立条件（同 shader、同材质参数）在复杂 UI 里是否仍然成立。
