# AI 在游戏生命周期的六个角色

一篇 2026 年的综述，把「AI 用于游戏」这件事按**输出的直接用途**分成六个角色。它的核心不是罗列系统，而是一个判断：**跨角色的输出可以复用，但复用不等于能力迁移**。

> 综述属二手综合，`confidence: medium`。本文只转述综述自己的框架与结论，不补充它未提及的方法细节。

> **收录范围说明**：本库的 arXiv 收编标准只覆盖「AI 用来做游戏」与「AI 用来理解玩家」。这篇综述的六个角色里，**玩与行动**、**构建与维护** 属于本库明确不收的范围（以游戏为测试床的 Agent 评测、编码 agent 代工游戏）。把它们留在表里是为了框架完整、便于对照，**不代表本库收编这两块内容**。本页定位是导航节点，不是方法页。

## 六个角色

| 角色 | 输出被用来做什么 |
|---|---|
| 玩与行动 | 做决策、发指令、与玩家或环境交互 |
| 建模玩家与世界 | 预测玩家行为、表征游戏动态、构建可交互模拟 |
| 设计游戏 | 产出资产、关卡、世界、规则、机制的候选 |
| 构建与维护 | 实现、修订、交接可执行的游戏工程 |
| 运行时生成与适配 | 在玩家正在玩的会话里改变体验 |
| 测试与评估 | 产出关于行为或质量的证据 |

分类依据是**输出被谁消费**，不是模型架构，也不是生命周期阶段。一个系统可以跨多个角色，主角色按「其主要实证结论所依赖的那个输出」判定。

## 核心论点：复用 ≠ 迁移

这是整篇综述最值得记住的一句：

> 复用（reuse）指一个可识别的输出被另一个任务消费；迁移（transfer）指在换了游戏、引擎、界面、玩家群体或任务之后，能力依然成立。**共享骨干或组件之间成功通信，都不足以证明后者。**

具体含义：

- 一条交互轨迹能当训练数据，但它的价值取决于接收方的任务——策略可能利用学习仿真器的错误
- 一个成功的搜索轨迹只在对应的规则和搜索条件下才算解，游戏被改动后不再成立
- 暴露中间表示（比如数值状态）是复用的前提，但不等于下游真的用了它

## 角色之间传的五类信息

综述把已实现的跨角色交换归为五类：

1. **交互轨迹** —— 可训练世界模型、可作为智能体经验、可作诊断证据
2. **想象经验** —— 从学到的环境里采样出的模拟经验
3. **规格与规则** —— 设计意图变成可执行实现
4. **执行与测试证据** —— 缺陷信息驱动修订
5. **玩家模型与画像** —— 驱动运行时适配

## 三个必须分开的验收问题

判断一个跨角色连接是否成立，综述建议拆成三问，且强调它们**不是一条逻辑链**：

| 问题 | 问的是 | 不能推出什么 |
|---|---|---|
| 兼容性 | 输出是否保留了接收方需要的格式与含义 | 不能推出「真的被用了」 |
| 使用 | 接收方在工作流中是否实际消费了这个输出 | 不能推出「有收益」 |
| 收益 | 相对合适基线，下游结果是否改善、代价多少 | — |

「兼容不等于使用，使用也不等于收益」——一个没测出下游改善的研究，依然有价值，因为它定位了连接的局限。

## 一个具体的技术路线

综述在第 10 节描述了一条正在成形的分工方式，值得单独记：

```text
设计意图 → 编码智能体 → 可执行灰盒（几何/控制/碰撞/目标/测试）
                        → 低成本的引擎渲染（含深度、遮罩、运动等缓冲）
                        → 状态条件视频模型合成最终画面
输入始终回到引擎，生成的像素不能反向改写碰撞或计分
```

这样做的收益是把「视觉丰富度」从「规则执行」里拆出来。难点随之转移到**可执行场景与玩家所见之间的一致性**：资产替换可能改变碰撞尺度，视频转绘可能在墙体位置画出门，渲染延迟可能显示过期状态。

综述明确说：完整的生产引擎组合**仍是研究方向**，轻量引擎的演示不足以证明 UE/Unity 工程级的生成与维护可行。

## 证据强度分布

综述对六个角色的证据成熟度给了不平等的评价：

| 较强 | 较弱 |
|---|---|
| 有界游戏对战 | 学习世界中的持久状态 |
| 部分已确立的学习环境 | 重复的软件修订 |
| — | 经验证的玩家建模 |
| — | 持续的运行时适配 |
| — | 有代表性的自动化测试 |

这个分布本身就是判断依据：**同一个「AI 能做 X」的说法，在不同角色里的证据强度差很远。**

## 反论与缺口

- **这是单一来源的框架，不是共识。** 六个角色的划分由作者提出，是否存在更合适的切法，综述本身没有论证。
- **角色边界有重叠。** 作者自己承认「角色在系统层面并不互斥」，主角色按「主要实证结论」判定，这带来主观空间。
- **「证据强度分布」是定性判断。** 综述没有给出量化的成熟度评分，强弱排序依赖作者对文献的解读。
- **没有成本视角。** 综述按「输出用途」分类，不讨论各角色的算力、标注、工程成本——而这往往决定一个团队能不能用。
- **未验证**：该框架在实际项目选型中的有效性。
