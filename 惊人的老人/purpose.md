# 知识库目标

系统积累游戏行业的两种知识：一是可长期复用的**游戏设计方法论**（玩法机制、关卡、数值、叙事、UX），二是**行业大事件的时序记录**（发布会、爆款、政策、厂商变动）。

目标不是攒笔记，而是让「某次事件当时是怎么说的」和「后来被验证成什么样」都能追溯，并把重复出现的设计判断沉淀成可复用的模式。

## 核心问题

1. 一个玩法机制为什么好玩？拆到可复用的设计语言是什么？
2. 某个品类是被什么事件或产品推起来的？时间线上的因果关系是什么？
3. 过去的设计判断在后续作品里成立吗？被推翻了吗？
4. 厂商和团队的策略变化，如何影响他们产出的游戏？
5. 哪些被当成「行业共识」的说法，其实缺乏证据？

## 研究范围

- **覆盖领域**：游戏设计（机制 / 关卡 / 数值 / 叙事 / UX / 心流）、游戏新闻大事件（发布会 / 爆款 / 政策 / 并购 / 人事）、厂商与团队、品类与市场
- **不覆盖**：玩家社区八卦、纯攻略流程、硬件评测、与设计无关的运营活动
- **时间边界**：新闻以**事件发生日**为准，不设起始年份
- **资料形态**：网页文章、公众号、研报 PDF、发布会视频与字幕、商店页与游戏截图

## 演进论点

> 这是工作假说，不是结论。每 10-20 次操作后回顾并更新。

截至 2026-11-02，本库刚建立，**尚无可验证的判断**。

首个待检验的假说：游戏设计知识的价值不在「技巧清单」，而在「什么条件下该技巧成立」。后续每沉淀一个设计模式，都要补上它的适用条件和反例。
